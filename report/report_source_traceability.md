## Inconsistencies and resolutions

- The repository name mentions complaints, but the final analysis contains sensor, pedestrian and CLUE records rather than complaint records. The report states this distinction and does not claim to analyse complaints.
- The pedestrian-count filename ends in `2019_2024`, while the file contains records through 2026. The report uses inspected contents and labels 2025 as the primary year.
- The current Python environment differs from the manifest by one `tzdata` patch version. This remains visible rather than being silently ignored.
- Seasonal order changes under strict balancing. The report presents all-available and balanced summaries rather than selecting one favourable result.
- The hospitality rank analysis was added after the fixed screen returned no candidate. It is labelled exploratory everywhere.
- The primary hospitality proxy sums two source categories with 166 exact venue keys in common. The union sensitivity leaves all candidate counts and the 500 m rank correlation unchanged, but the primary proxy must not be described as a unique-venue total.
- Several final scripts, outputs, figures, specifications and report files are uncommitted. The local working tree supports this assessment, but the remote repository does not yet constitute a complete final reproduction package.
