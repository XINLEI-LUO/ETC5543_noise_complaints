Preliminary Noise Sensor Exploratory Data Analysis

City of Melbourne Microclimate / IoT sensor data

Scope

This analysis is strictly descriptive. It audits and explores the noise measurements in data/raw/microclimate_sensors.csv.

The noise unit is labelled dataset units because the supplied file contains no metadata establishing a physical unit.

Reproducible analysis

The complete executable analysis is kept in analysis/noise_eda.R and is sourced below.

Code 
source("analysis/noise_eda.R")

Changing sensor composition

The pooled daily series does not hold the monitored sensor set constant. The table below reports the exact number and identity of devices with at least one valid noise observation in each month. Figure 6 shows the same information as a count series and sensor-by-month activity matrix. It demonstrates why Figure 1 must not be interpreted as a city-wide trend.

Figure 1 now inserts missing calendar dates before drawing lines, so it does not connect observations across outages. In the original version, the visually dominant rise between June and November 2022 was a straight line across a 158-day gap, not an observed daily trend. Exact daily identities and contiguous composition periods are saved as active_noise_sensors_by_day.csv and active_noise_sensor_periods.csv.

Balanced-sensor sensitivity

The balanced analysis uses ICTMicroclimate-01, ICTMicroclimate-02, and ICTMicroclimate-03 from 1 January 2023 through 30 June 2026. These are the three earliest noise-bearing sensors with a long common span. The endpoints use the first complete month after sensor 03 began and the last complete month before sensor 01 stopped. Noise is first summarised within sensor and week, then the median is taken across the same three sensors; only weeks containing all three are retained.

Spatial and sensor summaries

Sensor-level comparisons describe high- or low-noise monitored locations, not definitive Melbourne-wide hotspots. The network observes only its installed locations, and sensors have unequal temporal coverage.

The map uses the official City of Melbourne municipal boundary downloaded from the City of Melbourne Open Data Portal. Point size encodes each valid sensor’s median noise; aws5-0999 is marked separately because it has no valid noise observations. This remains a monitored-location map, not a city-wide hotspot map.

Noise metadata review

No local project file documents the noise unit, sensor model, calibration procedure, noise-specific quality flag, or interpretation of zero. The current City of Melbourne dataset page identifies Noise only as a decimal field and notes that 15-minute readings may be missing. A related historical official data dictionary documents units and quality flags for several other microclimate fields but does not include a noise sensor entry. Authoritative noise-specific metadata therefore still needs to be obtained or confirmed with the dataset owner; values remain labelled as dataset units, and zeros are retained as unresolved potential quality issues.
